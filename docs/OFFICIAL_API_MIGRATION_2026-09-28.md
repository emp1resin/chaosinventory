# Переход на официальные источники — проверяемый черновик

Рабочая версия GitHub Pages остаётся на main a93516fc06f53ebb2a1a17dbafc89b9fa05266a8.
Изменения находятся в PR #2, ветка fix/official-api-import. Сервер в backend/worker.mjs

## Что передал разработчик исходной примерочной

Пользователь сообщил, что часть методов chaosage.space отключалась владельцем
сервиса из-за наших запросов. Это объяснение владельца, а не доказательство причины
каждой ошибки Failed to fetch у каждого игрока. Старые сервисы больше не вызываются
из рабочей цепочки новой версии.

Переданы два Express-обработчика:

- getAvatarsDataByName: request + cheerio; HTML showInfo.php; характеристики из
  фиксированных индексов td[align=right], экипировка из массива картинок по ширине;
  два семейства колец различались по имени файла картинки; при исключении возвращался
  HTTP 200 с частично заполненным out и начальными характеристиками 5.
- religionAndClansData: последняя запись MySQL запросом
  `SELECT * FROM religionsAndClans ORDER BY date DESC LIMIT 1`; рейтинг кланов type=2;
  рейтинг религий type=4. Ответ отправлялся в callback запроса рейтинга религий, не
  дожидаясь запроса кланов и MySQL. Это реальная гонка: ответ мог быть неполным.

Разработчик подтвердил нестабильность старого парсера, наличие личного персонажа
для чтения храма, а также успешное получение clans из Python на ПК и удалённом
сервере. Python не ограничен браузерной CORS-проверкой; это не подтверждение
доступности нашего сервера из сети конкретного посетителя.

Новые переданные методы:

- https://chaosage.ru/sAPI2.php?request=clans
- https://chaosage.ru/sAPI2.php?request=user_religionBonuses&user_name=Материя

Рейтинги https://chaosage.ru/rating.php, type=2 и type=4 используются как
дополнительные публичные источники. Рейтинг религий содержит название, основателя,
количество последователей и артефактов; сам по себе не даёт полного набора личных
боевых бонусов.

Пустой объект религиозных бонусов пока не трактуется как доказанная спецификация
нулевых бонусов. Непустой неизвестный формат помечается, а не подставляется в формулы.
Иллириана по текущей логике продолжает давать нулевые религиозные бонусы.
На открытом рейтинге религий при проверке у всех восьми перечисленных религий
число артефактов равно нулю. Это согласуется с пустыми ответами, но не определяет
формат будущего непустого ответа. Для другой религии пустой ответ сопровождается
предупреждением о неподтверждённых бонусах.

## Реализация

1. Профиль берётся из открытой страницы через собственный сервер. Поля читаются по
   подписям в области params, без индексов строк и картинок. При противоречивых
   дубликатах или пропущенных обязательных полях импорт не подтверждается.
2. Кланы — официальный clans, позиция каждого персонажа — его строка в списке клана.
   Общая слава клана и личный коэффициент позиции остаются разными значениями.
3. JSON сначала запрашивается из игры, при сетевом сбое — через собственный сервер.
   После сетевого сбоя короткий перерыв перед повторными прямыми запросами.
4. Предметы читаются по ID экземпляра. Вариант из каталога определяется original_id.
   Две копии одинакового кольца получают независимые объекты состояния.
5. Одновременно читаются максимум три предмета; числовые руны Разлома разрешаются
   через API. Кэш экземпляров и запросов рун живёт только внутри одного импорта.
6. Все 11 полей списка обязательны. Пропущенное поле отличается от настоящего нуля.
   Повторный список в конце обнаруживает переодевание во время импорта. Изменение
   модификации у того же ID между запросами этим сравнением не обнаруживается:
   публичный API не даёт атомарный снимок или номер ревизии.
7. Redux получает одно действие после сборки всех обязательных данных. Старый
   запрос отменяется; ручные навыки, артефакты, бафы и данные религии сбрасываются.
8. Таймаут ограничивает чтение тела, а не только получение HTTP-заголовков.
9. Клиент и сервер различают HTTP, таймаут, сетевой/CORS-сбой, неверный JSON,
   отсутствующий слот и изменение экипировки. Браузерный Failed to fetch сам по
   себе не раскрывает, был ли это DNS, TLS, блокировка сети или скрытый CORS-ответ.
10. Отчёт одним нажатием содержит версию, этапы и позицию в клане. Размер ограничен
    в UTF-8 байтах и по серверной схеме. JSON отправляется как text/plain без
    предварительного OPTIONS. Сервер проверяет Origin и схему как раньше.
    Постоянные 4xx не удерживают очередь. Номер считается доставленным только
    после ответа сервера с совпадающим clientId. Если сервер вообще недоступен,
    доставка всё ещё невозможна до восстановления связи.
11. Сравнение билдов теперь передаёт тому же движку elixirs и golem: прежняя версия
    сохраняла их, но теряла при сравнении.
12. Ежедневное обновление конечного списка профилей отключено в новой конфигурации
    Actions. Этот файл больше не используется для импорта. Исторические данные
    остаются только для воспроизведения и тестов.

## Что ещё не доказано и мешает считать всю задачу закрытой

- Причина сетевого сбоя конкретного игрока в РФ: нужна проверка тестового домена
  из его браузера. Успех в Actions не заменяет её.
- Урон от клановой славы. В production код вообще не умножает damage на glory;
  значит, изменение позиции не может увеличить урон. Это установленная причина
  поведения примерочной, но правильная игровая формула ещё не подтверждена.
  Общий множитель давал 9111–11095 вместо контрольных 8047–9799. Без вещей
  базовый урон + маски давали 530–732, как у игрока. Слепо возвращать множитель нельзя.
- FAQ указывает коэффициенты позиции 100%, 98.5%, 97%; существующий код начинает
  с 98.5%. Нужен одновременный замер личного процента в игре и текущей общей славы,
  чтобы отделить ошибку индекса от изменения славы между замерами.
- Текущий Lich одет в другой, неполный комплект с булавой. Для сравнения формул
  нужен новый игровой снимок при известной текущей экипировке либо возврат
  прежнего полного комплекта, а не смешивание старых боевых цифр с новыми вещами.
- Непустой user_religionBonuses: пока нет примера для достоверного адаптера полей.
- Голем на открытой странице показывает наличие и уровень, но не подтверждает
  активный режим Поддержка. Автоматически прибавлять бафф по одной картинке нельзя.

## Границы проверки сети и порядок выпуска

- GitHub Actions получает свежие профили из сети своего runner. Это доказывает
  работоспособность официальных методов и нашего кода, но не доступ из конкретной
  российской сети.
- Браузерный прогон использует ответы, только что записанные живой проверкой;
  внешние запросы перехвачены для воспроизводимости. При этом DOMParser, React,
  Redux, localStorage и калькулятор настоящие. Успех этого прогона не доказывает
  фактическую CORS-политику развёрнутого нового сервера.
- CORS/сетевой отказ прямого JSON-запроса моделируется обрывом запроса, не
  отключением браузерной защиты. Отдельно моделируется отказ получения вещи.
- Однокнопочная отправка подтверждена до обработчика совместимого формата;
  запись новой версии в настоящую D1 требует проверки после обновления сервера.
- Старые домены отсутствуют в рабочей цепочке импорта. Неиспользуемый старый
  SaveGrid.jsx сохранён в репозитории, но нигде не импортируется и не входит
  в новый сценарий сохранений.

Публикация должна идти в таком порядке:

1. Обновить собственный сервер совместимым Worker; старый application/json
   по-прежнему принимается. Базу с существующими отчётами сохранить.
2. Проверить с Origin https://emp1resin.github.io: профиль с кириллицей, clans,
   equipment_info, religionBonuses; отправить один помеченный диагностический
   отчёт и подтвердить запись в D1.
3. Обновить GitHub Pages из проверенного PR; подтвердить, что версия отчёта
   соответствует новой сборке. Сохранения пользователей остаются под прежним ключом.
4. Проверить загрузку из сети игрока, который видел Failed to fetch. Если домен
   сервера недоступен в его сети, сменить размещение API; фронтенд уже позволяет
   задать VITE_CHAOS_API_BASE. Само GitHub Pages PHP/Node backend не исполняет.
5. Для отката вернуть клиент к a93516fc06f53ebb2a1a17dbafc89b9fa05266a8 и пересобрать.
   Новый сервер обратно совместим. Нельзя откатывать сервер, пока клиент использует
   новые методы и text/plain.
