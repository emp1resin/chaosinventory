# Архитектура проекта

## Общая схема

Проект — клиентское SPA-приложение:

- React 17;
- Redux 4;
- Vite 8;
- Material UI 4 и Bootstrap 5;
- статическая production-сборка без собственного сервера и БД.

Точка входа: `src/index.jsx`. Корневой компонент: `src/App.jsx`.

## Основные подсистемы

### Персонаж

- `CharInput.jsx` — уровень, характеристики, раса/высшая форма, религия, профессия, клан и благословения.
- `InputNameForFinding.jsx` — импорт по нику и обогащение данных ответами игровых API.
- `CharSingle.jsx`, `FreePointsChar.jsx` — поля характеристик и свободные очки.

### Предметы

- `ItemsAll.jsx` — сгенерированный локальный каталог предметов.
- `ItemsFit.jsx` — сетка экипировки.
- `ItemsList.jsx` — поиск, фильтрация и выбор предмета.
- `ItemInfoSystem.jsx` — модификации, обычные руны, рунные слова и руны Разлома.
- `scripts/update-catalog.mjs` — генератор каталога из FAQ и API.

`ItemsAll.jsx` нельзя редактировать вручную без необходимости: файл пересоздаётся командой `npm run update:data`.

### Навыки

- `SkillsProps.jsx` — список и описания навыков.
- `SkillsInput.jsx`, `SkillsSingle.jsx` — управление значениями и мастерством.
- `TooltipsSkillsInfo.jsx` — подсказки.

### Расчёт

- `Results.jsx` — основной и единственный актуальный движок расчёта итоговых параметров.
- Этот же компонент в безвизуальном режиме используется сравнением билдов.
- `DiffBuilds.jsx` и `LocalBuildForDiff.jsx` — выбор сохранений и визуализация различий.

Не создавайте второй независимый калькулятор: ранее это приводило к расхождениям между результатами и сравнением.

### Состояние

Всё состояние хранится в Redux:

- `src/reducers/postReducer.jsx`.

Reducer исторически мутирует вложенные объекты. При сохранении билда `SaveState.jsx` обязательно делает глубокую копию, чтобы последующие изменения не изменяли старые сохранения.

### Сохранения

- Хранилище браузера: `localStorage`.
- Ключ: `chaos-build-forge:saves:v1`.
- Регистрация, аккаунты и серверная БД отсутствуют.
- Очистка данных браузера удаляет сохранённые билды.

### Стоимость

`BuildCost.jsx` считает только подтверждённые данные:

- магазинную стоимость вещей в серебре;
- стоимость артефактов в золоте;
- стоимость обычных рун в очках контроля;
- стоимость свитков рунных слов в очках контроля.

Не считаются модификации, руны Разлома и аукционные цены: официальных формул либо фиксированных цен нет.

## Поток импорта персонажа

1. Пользователь вводит ник.
2. `getAvatarsDataByName` возвращает базовые данные и названия экипировки.
3. `sAPI2 user_equipment_list` возвращает ID экземпляров вещей.
4. Для каждого ID запрашивается `sAPI2 equipment_info`.
5. Числовой `breachRune` дополнительно разрешается через `equipment_info` самой руны.
6. Импортированные данные нормализуются и отправляются действием `Загрузка персонажа`.
7. Навыки заполняются вручную: открытый API их не возвращает.

## Production

`npm run build` создаёт каталог `dist/`. Его можно размещать на любом статическом хостинге.

Приложение во время работы обращается к внешним API и изображениям. Если новая платформа блокирует CORS или внешний трафик, потребуется собственный прокси.
